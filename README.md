# Apartment Radar 🏙️

서울 한강 이남·경기 남부 아파트를 지역/예산/면적별로 탐색하는 데이터 검증 우선 대시보드.

> **중요:** 현재는 사이트 구조를 먼저 구축한 **초기 버전**입니다. 기존 대화에서 언급한 후보 단지는 검증 대기 후보로만 수록했습니다. **가격과 TOP5는 두 독립 출처를 대조하여 승인된 자료만 표시**합니다. 화면에 수치가 없다고 해서 거래가 없다는 뜻은 아닙니다.

## 지역·예산·면적 자유 탐색 UI (v0.5, 2026-11-20)

- 지역: **서울 전체 25개 구**와 **경기 남부/인근 22개 시·구**를 시도 → 구/시 2단계로 선택. 확대된 지역 수집에 앞서 도로명/시군구 행정코드 목록 `data/regions.json`을 반영. 실제 데이터가 확보되기 전에는 무조건 "후보 없음"이라고 단정하지 않습니다.
- 매매 예산: **5~50억원**, 최소·최대 두 손잡이를 독립적으로 변경 (0.5억 간격).
- 전용면적: **59~165㎡**, 최소·최대 두 손잡이를 독립적으로 변경 (1㎡ 간격).
- 최종 검증된 TOP5: 500세대 이상 단지·거래 2중 출처/3건 이상 표본의 승인 정보만.
- 500세대 이상 **등록된** 단지의 잠정 비교: 국토부 1차 지번·면적·이름 일치 및 중개 신고 최대 5건을 기준으로 *자료의 풍부한 순서*로만 나열. 실제 세대수·독립 거래검증 전까지 "확정 매수 추천"이 아닙니다.
- 신규 추가 발견 단지: 전체 시군구 1차 신고에서 찾은 신규 후보. **500세대 확인 전, 2차 거래 검증 전**이므로 TOP5와 분리하고 가격·타입 참고만 허용.
- 범위 필터를 적용할 때 매매가격은 동일 세부 타입의 최근 5건 중개 신고 **중앙값**을 예산 범위와 비교하고, 최근 표본의 가격 상한을 넘는 거래가 있으면 추천 후보에서 제외. 이 조건은 원자료가 충실할 때만 의미 있으며 거래 부족·신고 지연을 명시합니다.

### 투자평가의 실제 구현 상태

| 평가 기준 | 장래 예정 가중치(합계 100) | 현재 상태 |
|---|---|---|
| 급지·장기 자산가치 | 핵심 생활권/교통 30, 재건축 진행·분담금 25, 수요 기반/학군 20, 희소성 15, 주택 품질 10 | **미산정** |
| 가격 매력도 | 비교단지 대비 가격 40, 전세가율·자본부담 20, 거래 추세 20, 거래 표본 20 | **미산정** |
| 동탄 출퇴근 | 출근시간대 실제 이동시간 60, 소요시간 변동성 20, 대안 경로 20 | **미산정** |
| 실거주 편의성 | 의료·상권 30, 대중교통·보행 25, 쾌적성 25, 관리·시설 20 | **미산정** |

이것은 **공개 설계 가중치**이고 자동 채점에 사용하는 점수가 아닙니다. 원천 데이터 없이 점수를 정하거나 대단지·입지에 임의 점수를 배정하면 안 됩니다. 현재 동작하는 정렬은 중개 매매 표본 많은 순, 최근 거래일 순, 중개거래 중앙값 낮은 순(1차)뿐입니다. 2차 출처 승인/지하철·정비사업·실측 통근·생활 편의 데이터가 들어온 후에만 점수 기능을 활성화합니다.

## 사이트 기능
- 세부지역(분당/금곡동 등) · 예산(10~15, 15~20, 부모님 20~30억원) · 전용면적 필터
- 지역별 TOP5: `검증 완료` + 500세대 이상 + 동일 타입 정상 중개거래 3~5건에 근거한 가격대만
- 검증 대기 후보 별도 노출; 숫자를 확정 시세로 표시하지 않음
- 단지별 매매·전세 데이터와 출처, 마지막 검증일, 24개월 실제 월별 거래점 차트(데이터 존재 시에만)
- 주간 수집·검증 상태 표기

## 데이터 검증 규칙
1. 이름만으로 거래를 결합하지 않고 주소/지번/단지 ID·면적 타입을 맞춥니다.
2. 총세대수 500세대 이상, 주소·준공·타입을 서로 독립된 두 출처에서 확인해야 `정적정보 검증`으로 인정합니다.
3. 국토부 기반 매매자료와 독립적인 두 번째 서비스의 **건별** 날짜·층·금액을 대조합니다.
4. 직거래·해제 거래는 정상 중개매매/가격 산정에서 제외합니다. 이상 거래는 단정하지 말고 수동 검토합니다.
5. 전세는 신규/갱신/계약조건을 구분하고, 검증된 동일면적 신규계약 3~5건으로 범위를 표시합니다.
6. TOP5는 모든 필수 정보가 유효한 후보가 5개 미만이면 그만큼만 표시합니다.
7. 월별 24개월 그래프는 실제 검증된 거래가 있는 월만 점을 찍고 나머지는 비워둡니다.
8. `verified=true`는 데이터 구조에 출처 2개와 마지막 검증일·매매·전세 증빙이 있을 때만 유효합니다. (정량 점수는 기준 변경과 함께 공개합니다.)

## 국토부 자동 수집 (v0.2)
수집은 **국토교통부 1차 공공 신고자료**로만 이루어지며, 독립 2차 출처 교차검증을 대체하지 않습니다.

### 1. API 활용 신청 및 비밀키 등록 (사용자가 수행)
1. [아파트 매매 실거래가 **상세자료**](https://www.data.go.kr/data/15126468/openapi.do)에서 `활용신청`.
2. [아파트 **전월세** 실거래가 자료](https://www.data.go.kr/data/15126474/openapi.do)에서도 `활용신청`. 동일 공공데이터 서비스키로 두 서비스에 대한 사용 승인이 있어야 합니다.
3. [저장소 Actions secrets](https://github.com/sysjkwon3006-ui/apartment-radar/settings/secrets/actions) → **New repository secret** → 이름 `MOLIT_API_KEY` → 공공데이터포털 발급 일반인증키 값을 입력 후 저장. **채팅·커밋·코드·Cloudflare 빌드 변수에 키를 붙여 넣지 마세요.**
4. [Weekly MOLIT workflow](https://github.com/sysjkwon3006-ui/apartment-radar/actions/workflows/weekly.yml) → **Run workflow** → Branch `main`, `months=3` → **Run workflow**.
5. 초록색 성공 표시 이후 [국토부 1차 수집 현황](https://apartment-radar.pages.dev/primary.html)에서 지역별 집계/신고내역 확인. 실패하면 GitHub Actions 실행 로그의 **어떤 단계에서 실패했는지** 확인.

GitHub Actions는 **매주 토요일 07:15 KST(금요일 22:15 UTC)** 에 19개 시군구의 **최근 3개월(당월 포함)** 아파트 매매·전월세 자료를 조회하고, 80~90㎡ 및 100~135㎡만 `data/molit/latest.json`에 **1차 수집 상태**로 저장합니다. 마지막 수집 시각은 `data/site-meta.json`에 저장됩니다. 자동으로 `data/complexes.json`의 `verified` 값을 바꾸지 않습니다.

- API 오류, 권한 부족, 누락된 키 또는 페이지 조회 오류 때는 작업이 실패하며 이전 검증된 시세를 덮어쓰지 않습니다.
- 신고 지연·해제·정정에 대비해 최근 3개월을 매번 재조회합니다.
- 화성시 동탄구는 2026년 개편 코드 `41597`을 사용합니다. 법정동 코드 변경 때는 `data/regions.json`을 업데이트해야 합니다.
- 초기 24개월 백필은 추후 **지역별·월별 파일 분할** 및 트래픽/호스팅 크기 점검 후 진행하는 것이 안전합니다. 24개월 전체를 한 파일로 무분별하게 수집하지 마세요.
- **검증 기준:** 국토부 자료 + 허가된 독립 서비스의 계약일·층·면적·가격 대조, 취소·직거래 제외, 신규 전세 확인, 동일 주소/지번/타입 매칭 후에만 TOP5에 반영합니다.
- 검증 테스트: `python -m unittest discover -s scripts -p 'test_*.py' -v`, 승인자료 검증: `python scripts/validate.py`.

### 코드·데이터 경로
```
index.html                        # 지역별 TOP5 (확정 데이터만)
primary.html / primary.js         # 국토부 1차 수집 현황 (미검증)
data/regions.json                 # 현행 법정동코드 19개
data/molit/latest.json            # 성공적인 첫 수집 이후 생성 (1차 자료)
data/site-meta.json               # 마지막 실행/승인 시각을 구분
scripts/collect_molit.py          # XML API 조회·페이지네이션·정규화
scripts/test_molit.py             # 네트워크 없는 가상 응답 테스트
.github/workflows/weekly.yml     # 토요일 수집, 성공 시 변경사항 커밋
.github/workflows/check.yml      # 코드·데이터 변경 시 오프라인 검사
```

**단계 구분:** 사이트가 정상 배포되었다고 API가 연결된 것은 아닙니다. Secret 등록과 첫 workflow 실행 성공까지는 **자동 수집 미가동** 상태입니다.

## 단지별 잠정 매칭 검토 v0.3

국토부 1차 수집 17,463건(2026-11-18 첫 실행)에 대해 **시군구코드·법정동·정확한 지번·전용면적 타입**이 동시에 맞는지를 점검하고, 단지명까지 대조해 1차 매칭 후보를 만듭니다. 매칭 대기열을 보고 추가 출처를 확인하는 작업은 별도로 필요합니다.

- [단지 매칭 검토 페이지](https://apartment-radar.pages.dev/matches.html): 일치 기록/단지명 추가 확인/직거래·취소·신규 전세 분리
- scripts/match_candidates.py: 임의 유사도 매칭 없음. 면적차 허용은 0.009㎡.
- scripts/test_matching.py: 지번·지역·면적·이름 충돌 및 미확인 거래 테스트
- data/matches/latest.json: 1차 매칭 후보(일자 및 원장 일부), **투자 확정 시세 아님**
- .github/workflows/match_on_change.yml: 후보·코드 변경 시 대기열 자동 재생성, 수동 실행 가능
- .github/workflows/weekly.yml: 매주 국토부 수집 직후 매칭 대기열까지 함께 갱신
- [2차 출처 검증 체크리스트](docs/review-guide.md)

초기 결과: 잠정 매칭 192건(단지명까지 129건, 이름 추가 검토 63건), 관심 단지 18개 중 15개에서 신고자료 발견. 정확한 지번이 누락된 3개 단지는 매칭 보류. **독립 2차 출처 확인은 여전히 0건이므로 TOP5는 자동 채워지지 않습니다.**

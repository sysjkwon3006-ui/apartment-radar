# Apartment Radar 🏙️

서울 한강 이남·경기 남부 아파트를 지역/예산/면적별로 탐색하는 데이터 검증 우선 대시보드.

> **중요:** 현재는 사이트 구조를 먼저 구축한 **초기 버전**입니다. 기존 대화에서 언급한 후보 단지는 검증 대기 후보로만 수록했습니다. **가격과 TOP5는 두 독립 출처를 대조하여 승인된 자료만 표시**합니다. 화면에 수치가 없다고 해서 거래가 없다는 뜻은 아닙니다.

## 사이트 기능
- 세부지역(분당/금곡동 등) · 예산(10~15, 15~20, 부모님 20~30억원) · 전용면적 필터
- 지역별 TOP5: `검증 완료` + 500세대 이상 + 동일 타입 정상 중개거래 3~5건에 근거한 가격대만
- 검증 대기 후보 별도 노출; 숫자를 확정 시세로 표시하지 않음
- 단지별 매매·전세 데이터와 출처, 마지막 검증일, 24개월 실제 월별 거래점 차트(데이터 존재 시에만)
- 주간 수집·검증 상태 표기

## 구조
```
index.html
styles.css
app.js
data/complexes.json         # 단지 원장 + 필터·검증상태
data/site-meta.json         # 업데이트 상태
scripts/validate.py         # 저장소 데이터 스키마/검증상태 점검
.github/workflows/weekly.yml# 토요일 정합성 검사 및 재배포 준비
```

## 데이터 검증 규칙
1. 이름만으로 거래를 결합하지 않고 주소/지번/단지 ID·면적 타입을 맞춥니다.
2. 총세대수 500세대 이상, 주소·준공·타입을 서로 독립된 두 출처에서 확인해야 `정적정보 검증`으로 인정합니다.
3. 국토부 기반 매매자료와 독립적인 두 번째 서비스의 **건별** 날짜·층·금액을 대조합니다.
4. 직거래·해제 거래는 정상 중개매매/가격 산정에서 제외합니다. 이상 거래는 단정하지 말고 수동 검토합니다.
5. 전세는 신규/갱신/계약조건을 구분하고, 검증된 동일면적 신규계약 3~5건으로 범위를 표시합니다.
6. TOP5는 모든 필수 정보가 유효한 후보가 5개 미만이면 그만큼만 표시합니다.
7. 월별 24개월 그래프는 실제 검증된 거래가 있는 월만 점을 찍고 나머지는 비워둡니다.
8. `verified=true`는 데이터 구조에 출처 2개와 마지막 검증일·매매·전세 증빙이 있을 때만 유효합니다. (정량 점수는 기준 변경과 함께 공개합니다.)

## 매주 자동화 준비
GitHub Actions `weekly.yml`은 **토요일 07:15 KST(금요일 22:15 UTC)**에 실행되어 저장소 데이터의 유효성을 점검합니다. API 키/독립출처 연동이 아직 없으므로 **새 거래를 자동으로 수집하거나 검증 완료 처리하지 않습니다.** 이것은 의도적인 안전장치입니다.

실제 자동 갱신을 위해 별도 작업:
- 공공데이터포털 서비스키를 GitHub Actions Secret `MOLIT_API_KEY`로 구성
- 대상 시군구 법정동코드와 단지 식별/동일 타입 매칭 파이프라인 구축
- 라이선스 및 이용 조건에 맞는 2차 출처 대조·승인 단계 연결
- 검증 완료 JSON 갱신 및 변경 이력 기록
- Cloudflare Pages에 GitHub 저장소 연동 (프로젝트 이름 `apartment-radar`, 프레임워크 None, 출력 디렉터리 `/`)

## 주의

- `pages.dev` 호스팅은 사이트를 기본적으로 공개할 수 있습니다. 개인 전용이면 Cloudflare Access 등 접근 제어를 별도 설정해야 합니다.
- GitHub 예약 실행은 지연될 수 있고 작업 성공과 데이터 신규 갱신은 다릅니다.
